# The big one — D1, the share chain

**The URL scheme is decided here, because URLs are a one-way door.** Ids are already
`r-<sha1>`, stable across renames. So:

- `/r/<id>/` — one served `index.html` per resource, generated by the build. Same shell
  as `resource.html`, same JS rendering from data, but `<title>`, `og:title`,
  `og:description`, `og:url`, `canonical` filled at build time. Description is the
  `For:` line; if it is under 120 characters, the first sentence of `Skip if:` follows
  it. `og:image` is one site image for now — a per-format image is a later round.
- `/c/<role>/<level>/` — one page per cell, forty of them, title in the site's own
  words (*Claude for a teacher who has never used it — Learn Claude*), description the
  three picks' titles. The teacher's closing answer was "send the beginner cell to
  colleagues"; a cell is a share unit.
- `/p/<slug>/` — one page per path, seven, title and the path's opening line.
- `resource.html?id=`, `browse.html?role=&level=`, `paths.html#` keep working and send
  the browser to the canonical page. **Copy link copies the canonical URL.** The sitemap
  lists canonical URLs only.

Write `docs/specs/2026-09-07-share-chain.md` first — one page: the scheme above, what
the build generates, what the size of the output is, and how the old URLs redirect.
Then build it. Verify with a real unfurl: paste one resource, one cell and one path
link into a preview debugger and put the screenshots in the round record. Then
`test-gates.py` learns to plant a missing `og:title` and watch the build go red.

## D12 — verified, and nothing was changed

The ruling was to make sure nothing on the resource page swallows a selection. It does
not. Each judgement sentence was selected by a real drag in a browser and read back out
of `window.getSelection()`:

- "Who it's for" — selects, whole.
- "Skip it if" — selects, whole.
- "How we checked this one" and the provenance line — select.
- "Where this fits", the path line — a plain paragraph, no overlay above it.

There is no `user-select` rule anywhere in the stylesheet, and `elementFromPoint` over
each paragraph returns the paragraph itself.

**But the same test on the path page fails.** A step's `why` — the site's own argument
for putting that resource at that position — cannot be selected at all. `.sp-title a`
carries a stretched `::after` covering the whole step block, and `elementFromPoint` over
the `why` returns that link. Selection there returns an empty string.

That is not the resource page and the ruling said cards keep the stretched link, so
nothing was changed. It is a new finding, reproducible, and it wants a ruling: the path
page is the one place a reader would quote a sequence from, and its argument is the part
they cannot copy.

## D9 in full — why the tag was missed, measured rather than guessed

Two faults, and neither alone would have found the row.

1. `audit-role-tags.py` answered a `who_for` opening "Anyone …" with `continue`. The
   ruling behind that skip is about the direction that *drops* tags. Implemented as a
   skip it silenced the direction that *adds* them, on 168 rows.
2. The role vocabulary names each role by its job title — writer, copywriter, journalist,
   editor. The card names the job as an activity: "Anyone who writes a lot of internal
   communication". A reader can be named by what they do, and the rule had no way to hear
   it.

The activity pattern is qualified by frequency, and the width was measured before it was
chosen: a bare `\bwrites?\b` matches 32 rows in this catalogue and `\bwriting\b` matches
34, nearly all of them developers writing code or skills. Qualified — "writes a lot",
"for a living", "professionally", "all day", "every day" — it matches one row, and it is
the right one. With the tag removed again the rule proposes it by name.

Lifting the skip adds 5 suggestions beyond that one, and all five are wrong: "newsroom
ownership" read as an owner, "doesn't have design skills" read as a designer. That is the
cost of a direction that cannot delete anything, and it is the right side to be wrong on
— a bad suggestion is read and ignored, a missing one is a reader who never finds the
page. A neutral card suggesting `non-technical` is the opening-word test restating
itself, so that one is suppressed; it was most of what the branch would have printed.

## Constraint 5 — the one stated departure

Ruled: a pick's `who_for` may not name a roster role other than the cell's.

Implemented: naming another role **and never this reader** is an error. Naming this
reader **and another beside them** is a note, printed every run.

The reason is that `who_for` belongs to the item and not to the cell. Dropping "graduate
students" from "Researchers and graduate students" to satisfy the researcher cell breaks
the student cell that picks the same thing, so the only way to satisfy the strict version
is to stop picking anything that serves more than one job. Run strictly the rule flags 21
picks; run as implemented it flags 1 — and that 1 is exactly the pick that was reported,
"For: Any analyst" on the student's shelf. The other 20 are printed as notes so the strict
version can be judged from a list.

## The gates

Every gate has a bite test, and the harness plants each fault and watches the build go
red. Two were added this round.

| planted fault | the build goes red saying |
|---|---|
| a listed row carrying a verdict | `tier is listed` |
| a question that is a suite query | `check-questions.py` |
| a suite query forced to miss | `REGRESSION` |
| a content gap with no evidence | `A content gap is a claim about the` |
| a synonym with no reason | `validate-synonyms.py` |
| a dead pick | `validate-picks.py` |
| a typed count in a pick's reason | `check-typed-numbers.py` |
| a live count typed into a document | `state a count with no date beside` |
| **a surface building its own freshness line** | `never asks for the freshness line` |
| **a path step the catalogue knows is superseded** | `superseded step` |
| share pages keeping their placeholder head | `serves the shell's placeholder` |

An untouched copy builds green. `scripts/test-validate-picks.py` carries its own set,
which gained the constraint-5 fault this round.
