# URL endings that are allowed to appear on more than one host.
#
# scripts/validate-catalogue.py's title check (data/duplicate-titles.txt) missed four
# migrated-to-Academy duplicates on 2026-08-29 because their titles differed by a word or
# a dash - "(Academy)" appended, an extra "- two classroom workflows" on the older row, a
# stray "tutorial" in one title but not the other. The URL did not lie: all four carried
# the identical trailing path segment on claude.com/resources/tutorials/ and
# academy.claude.com/tutorials/, because one page is Anthropic's own copy of the other. A
# slug is meant to be unique to the resource it names, so two hosts sharing one is the
# stronger signal - it catches what a title collision cannot, and it does not care what
# either row happens to be titled.
#
# One title per... no: one URL ENDING per line here, same shape as duplicate-titles.txt.
# Everything after a `#` is the reason, and the reason is the point, for the same reason
# it is the point over there: a bare allowance list becomes a place to silence the check.
#
# Add a line here only when the two entries really are different resources. If they are
# the same thing on two hosts, merge them instead and delete nothing from this file.
#
# youtube.com and youtu.be are compared by full normalised URL instead of by trailing
# path segment, because every video on that host ends in the literal word "watch" with
# the real identity in the query string - comparing bare segments there would collide
# every video in the catalogue into one false group. See url_slug() in
# scripts/validate-catalogue.py.
#
# First run, 2026-08-29: 16 hits. One was a real duplicate (see duplicate-titles.txt's
# resolved section - "plan your literature review", merged into one row). These 15 are
# not. Checked individually rather than assumed, because "checked, kept as a separate
# entry" without checking is exactly the mistake that let four migrated duplicates sit
# in this catalogue past the title check for two rounds before a person found them.
